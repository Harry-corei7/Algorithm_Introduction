- 返回插入之后的 intervals。
  - **注意**你不需要原地修改 intervals。你可以创建一个新数组然后返回它。

## 深入理解 Python Lambda：它真的很难吗？
> 一句惊醒：“lambda 很难理解？狗屁！” —— 它不过是个没有名字的 def。

#### 1. Lambda 的本质：与 def 完全等价

```python
# 写法 A：普通函数
def add_one(x):
    return x + 1

# 写法 B：Lambda 表达式（完全等价）
add_one = lambda x: x + 1
```
- 结论：
- `lambda x: 表达式`就是`def 无名(x): return 表达式`的简写。
- 你会写`def`，就会写`lambda`。

#### 2. 为什么 Lambda 会让人困惑？
- 绝大多数困惑并非来自 lambda 本身，而是来自不知道它的参数是从哪里传进来的。
- 看这行代码：
```python
result = some_function(lambda z: z ** 2)
```
- 你一眼能看出`z`是什么吗？
- **不能！** 除非你深入`some_function`的内部实现，才知道它调用`lambda`时括号里塞了什么。

#### 3. 解决困惑的标准模式：高阶函数 + 回调
- 几乎所有让`lambda`显得“神秘”的场景，都遵循同一个设计模式：
> 一个函数（框架）留出一个参数位置（形参），用于接收一个可调用对象（回调），然后在内部某个时刻调用它，并决定传入什么参数。
- 我们用中文注释 + 标准 Python 代码，把这个模式固化下来：

```python
# 1. 定义框架：函数留出一个“操作”插槽
def framework(data, sub_function):
    """
    sub_function 是一个占位符（可调用对象），
    由调用者在实际使用时注入具体的操作。
    """
    # 一些预处理（例如归一化）
    normalized = normalize(data)
    
    # 框架（调用者）决定往 sub_layer 里塞什么参数
    # 这里把 normalized 作为参数传进去
    output = sub_function(normalized)
    
    # 后续其他逻辑...
    return output
```

#### 4. 使用方式 1：注入一个 Lambda 表达式

```python
result = framework(
    raw_data,
    lambda z: z ** 2          # 这个 lambda 就是 sub_function 的具体实现
)
# 在 framework 内部：sub_function(normalized) 等价于 lambda z: z**2
# 此时 lambda 里的 z 接收到的值就是 normalized（归一化后的数据）
```

#### 5. 使用方式 2：注入预先定义的函数或模块

```python
# 普通函数
def my_function(z):
    return z + 10

result = framework(raw_data, my_function)   # sub_function = my_function
```
